# ☕ 내 카페를 아는 AI 파트너 (my-cafe-agent) — 배치2 [Context+Agent+DB]

`my_cafe.md`(컨텍스트) + 운영 DB(`cafe_sales`)를 **둘 다** 읽어 "내 카페에 딱 맞는" 운영 조언을 주는 AI 파트너. 일반론이 아니라 이 카페의 컨셉·제약·실매출에 근거해 답한다.

## 구성
- `my_cafe.md` — 카페 컨텍스트(상호 데일리브루·컨셉·시그니처·가격대·**제약(좌석24/인력2/주방협소/예산)**·운영목표).
- `.claude/agents/cafe-partner.md` — 에이전트 정의. 도구: `Read`, `mcp__supabase__execute_sql`, `list_tables`.
- `DEMO.md` — **Before/After 비교, 실제 실행 기록**.

## 핵심 설계 (맞춤성)
- 답하기 전 항상 두 소스를 읽는다: ① `my_cafe.md`(Read) + ② `cafe_sales`(execute_sql).
- 모든 조언은 컨텍스트 제약 + 실데이터를 **둘 다** 반영. 제약 위반 제안(좌석 증설·대규모 신메뉴·고비용 마케팅) 금지.

## 어떻게 검증했나 (이번 세션)
에이전트를 **실제로 띄워** `my_cafe.md`를 Read하고 라이브 `cafe_sales`(63행, 2026-06-21~27, 매출 4,191,000원)에 쿼리하게 했다. `DEMO.md`는 3개 운영 질문의 **[Before: 컨텍스트 없는 일반론] vs [After: 컨텍스트+데이터 답]** 비교 + 핵심 인사이트다. 발견 예:
- 통념과 반대로 **고가 치즈케이크는 평일(16개/일)**, **저가 초코쿠키는 주말(25개/일)** 에 몰림 → "평일은 단가, 주말은 물량" 운영 원칙.
- 평일 음료가 구조적으로 약함(주말 대비 29%↓) → 좌석·인력 증설 없이 가능한 무비용 개선 제안.
- 에이전트가 데이터 한계(시간대·원가 컬럼 없음)도 정직하게 명시.

## 사용법
```
@cafe-partner 평일 낮 매출 어떻게 올릴까? / 신메뉴 추가할까? / 주말 대기·품절 어떻게 해?
```

## 출처
컨텍스트(`my_cafe.md`)·에이전트 정의는 Week5-1 참고본에서 이식, **DEMO.md(Before/After)는 이번 세션에 실제 에이전트를 돌려 새로 생성·검증**했다.
