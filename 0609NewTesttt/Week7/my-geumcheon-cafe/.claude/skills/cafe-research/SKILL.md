# 관심분야 자동 리서치 — 가산 오피스 카페 경쟁·트렌드 주간 모니터링

매주 반복하는 '웹 리서치 → md 정리 → 노션 공유' 작업을 이 절차대로 재현한다.
기준 데이터는 항상 `_mission/my_cafe.md`(내 카페 = "여덟 시 반": 가산디지털단지, 사전주문 픽업 스페셜티 + B2B 디저트박스)를 참고한다.

## 언제 쓰나
- 매주 1회 가산 경쟁 카페/오피스 상권/B2B 수요 동향을 점검하고 싶을 때
- "카페 리서치 돌려줘" / "이번 주 가산 카페 뭐 바뀌었어?" / "오피스 커피 트렌드" 요청 시

## 절차

1. **주제·키워드 확인** — 사용자에게 이번 주 초점을 묻는다 (기본값: 가산·구로 경쟁 카페 + 오피스 커피/구독 트렌드 + B2B 간식 수요). 답이 없으면 기본값으로 진행.

2. **웹사이트 3곳 이상 탐색** — WebSearch/WebFetch(또는 브라우저 MCP)로 아래 축을 각각 훑는다:
   - (a) **오피스 상권·직장인 소비** 트렌드 소스 (상권분석 리포트, 커피 구독·B2B 뉴스)
   - (b) **경쟁 상권**(가산·구로디지털단지) 카페 큐레이션/순위
   - (c) 개별 **경쟁사 신메뉴/가격/영업시간** (다이닝코드·블로그·인스타)
   - 최소 3개 출처, 가능하면 5개.

3. **아래 포맷으로 `_signals/feedback/research/cafe-research-{YYYY-MM-DD}.md` 작성** (world 모델: 리서치는 signals로 들어온다):
   ```markdown
   # 카페 주간 리서치 — {날짜}
   ## 수집일 / 초점
   ## 출처별 핵심 (출처마다 3줄)
   ## 이번 주 트렌드 한 줄 요약
   ## 경쟁사 동향 (내 카페 대비)
   ## 다음 액션 (내 카페 "여덟 시 반" 적용안 2~3개)
   ```

4. **world 모델 반영** — "다음 액션"에서 바로 실행할 것이 나오면 해당 목표 폴더의 `_goal/<목표>/plan.md`에 추가하고(맞는 목표가 없으면 `_goal/README.md` 스코어보드에 새 목표 제안), `_daily/{YYYY-MM-DD}.md`에 논의/결정 한 줄을 남긴다.

5. **노션 공유** — Notion MCP가 있으면 결과 md를 노션 페이지로 올린다(없으면 파일만 저장하고 안내).

## 산출 원칙
- 트렌드는 **내 카페에 적용 가능한 형태**로만 남긴다 (뉴스 요약 X → "그래서 우리 모닝세트/디저트박스에 뭘?")
- 경쟁사는 **이름 + 가격/영업시간 + 우리와의 차이** 3요소로 기록 (오피스 상권은 시간대·가격이 무기)
- 매주 같은 포맷 → 주차별 비교가 쌓이게 한다

## 핵심
에이전트는 한 번, 스킬은 매번. 이 절차를 박제해두면 "리서치 돌려줘" 한마디로 매주 같은 품질의 카페 리포트가 재현된다.
