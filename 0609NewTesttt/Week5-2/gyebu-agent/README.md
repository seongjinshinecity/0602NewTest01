# 🧮 가계부 소비 분석가 (gyebu-agent) — 배치2 [Agent+DB]

가계부 Supabase DB(`transactions`)에 연결해 **"말로 물어보는 소비 분석가"**. 기본 조회·패턴 분석·절약 조언을 모두 실제 SQL 결과에 근거해 답한다.

## 구성
- `.claude/agents/gyebu-analyst.md` — 에이전트 정의(페르소나·규칙·도구). 도구: `mcp__supabase__execute_sql`, `list_tables`.
- `DEMO.md` — **실제 실행 기록**(아래 검증 참고).

## 핵심 설계 (정확성)
- 추정·암산 금지: 모든 숫자는 `execute_sql` 결과만. 합산/평균은 SUM/AVG/GROUP BY로 DB에 시킨다.
- `transactions` 테이블만 사용(같은 프로젝트의 posts/cart/cafe_sales는 무시).
- 데이터에 없으면 "없다"고 답(지어내지 않음).

## 어떻게 검증했나 (이번 세션)
이 에이전트를 **실제로 띄워** 라이브 Supabase `transactions`(204행, 2026-03~06)에 직접 쿼리하게 했다. `DEMO.md`의 8개 질문(조회/패턴/조언) 답변과 수치는 전부 에이전트가 실행한 SQL 결과다. 예:
- 6월 지출 1,169,026원(수입의 39%) · 카테고리 1위 주거 47.0% · 식비 28.9%
- 주말 일평균 55,819원 = 주중(36,515원)의 약 1.5배
- 절약 1순위 = 식비(변동비 최다·빈도 최고) → 주말 식비 상한 제안

## 사용법
Claude Code에서 Supabase MCP가 연결된 상태로:
```
@gyebu-analyst 이번 달 얼마 썼어? / 주중 vs 주말 비교해줘 / 줄일 것 추천해줘
```
> 가이드는 "가계부 앱과 같은 Supabase 프로젝트"를 권장한다. 본 데모는 운영 데이터가 충분히 쌓인(204행) Supabase 프로젝트를 대상으로 했다. 배치1 budget-app과 완전히 통합하려면 둘을 같은 프로젝트/테이블에 맞추면 된다.
