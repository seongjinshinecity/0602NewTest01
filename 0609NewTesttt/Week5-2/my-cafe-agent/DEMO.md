# DEMO — 데일리브루 운영 파트너 (Before/After, 실제 에이전트 실행 기록)

> 아래는 `cafe-partner` 에이전트를 **실제로 띄워 `my_cafe.md`를 Read + Supabase `cafe_sales`(63행)에 직접 쿼리**하게 한 결과다.
> [Before]는 컨텍스트·DB 없이 일반 챗봇이 줄 법한 답, [After]는 이 에이전트가 컨텍스트+실데이터로 준 답이다. 모든 수치는 에이전트가 실행한 SQL 결과다.

---

> **무엇을 봤나**
> - **컨텍스트**: `my_cafe.md` — 데일리브루(성수동 디저트 스페셜티 카페). 시그니처 치즈케이크·크로플, 커피 4,500–5,500원·디저트 3,000–6,500원. 제약: **좌석 24석(확장 불가)·인력 2명·주방 협소·예산 제한**.
> - **운영 데이터**: Supabase `public.cafe_sales`, 기간 **2026-06-21(일)~06-27(토), 7일**. 9개 메뉴·3개 카테고리, 총 **845잔/개**, 매출 **4,191,000원**.
> - **데이터 한계(중요)**: 컬럼은 `date(날짜만)·menu_name·category·quantity·amount`뿐. **시간대(hour)·재고·원가 컬럼이 없다**. 따라서 "시간대"는 요일/일자 단위로, "마진/품절"은 컨텍스트와 결합해 추론한다. 요일별은 1일치(n=1) 스냅샷이라 결론은 **7일 합계와 평일/주말 묶음(5일 vs 2일)** 위에 둔다.

---

### Q1. 평일 낮 한산한 시간대 매출을 어떻게 올릴까?

**[Before — 컨텍스트 없음]**
"점심 외 시간엔 타임세일이나 1+1 음료 프로모션, SNS 쿠폰을 돌려서 손님을 유도하세요." (어느 카페에나 통하는 일반론, 매장 메뉴·제약 무시)

**[After — 내 카페 파트너]**
- 실행 쿼리:
  ```sql
  SELECT to_char(date,'Dy') AS day, SUM(amount) AS amount FROM public.cafe_sales GROUP BY date ORDER BY amount;
  SELECT CASE WHEN EXTRACT(DOW FROM date) IN (0,6) THEN '주말' ELSE '평일' END AS daytype,
         category, ROUND(SUM(amount)::numeric/COUNT(DISTINCT date)) AS amt_per_day
  FROM public.cafe_sales GROUP BY 1,2 ORDER BY 1,3 DESC;
  ```
- 결과: 일평균 매출 **평일 600,100원 ≈ 주말 595,250원**으로 거의 동일 → 부진은 "평일 전체"가 아니라 특정 평일/시간대 문제. 평일 음료가 **92,200원/일(주말 130,000원/일 대비 약 29%↓)** 로 가장 비어 있는 칸.
- 답변(제약 반영):
  1. **평일 오후 '카공 세트'**: my_cafe.md의 카공 친화·콘센트/와이파이 강점 활용해 커피+디저트 소액 묶음. 신규 설비·인력 0, 주방 부담 0.
  2. **평일 음료 보강**: 구조적으로 약한 음료(자몽에이드·아이스티)를 오후 한정 입간판으로 노출(메뉴 추가 아님).
  *진짜 "한산 시간" 입증엔 시간대 데이터 필요 → 영수증 시간 기록을 1~2주 모으면 정밀 타겟 가능.*

### Q2. 신메뉴를 추가하는 게 좋을까? 뭘 기준으로?

**[Before — 컨텍스트 없음]**
"요즘 유행하는 신메뉴(말차·두바이초콜릿 등)를 넣어 트렌드를 따라가세요." (주방·인력 제약 무시)

**[After — 내 카페 파트너]**
- 실행 쿼리:
  ```sql
  SELECT category, SUM(amount) amount, ROUND(100.0*SUM(amount)/SUM(SUM(amount)) OVER (),1) pct FROM public.cafe_sales GROUP BY category ORDER BY amount DESC;
  SELECT menu_name, SUM(quantity) qty, SUM(amount) amount FROM public.cafe_sales GROUP BY 1 ORDER BY amount DESC;
  ```
- 결과: 커피 47.0% · **디저트 35.8%** · 음료 17.2%(최약). 매출 1위 **치즈케이크 617,500원(95개)**, 3위 크로플 534,000원. 수량 1위 초코쿠키 116개지만 매출 348,000원(단가 3,000원).
- 답변(판단 기준 명시): 추가 규칙 = ① 주방 부하 낮음 + ② 약한 칸 보완/객단가↑ + ③ 시그니처 자산 재활용. **새 카테고리·복잡 신메뉴는 보류**(인력 2·주방 협소 위반). 대신 **1위 치즈케이크의 시즌 변형 1종**(같은 오븐·공정, 토핑만 교체)으로 객단가↑. 저단가 초코쿠키는 세트 구성품으로 흡수.

### Q3. 주말 피크 대기/품절 문제를 어떻게 다룰까?

**[Before — 컨텍스트 없음]**
"좌석을 늘리고 직원을 더 뽑거나 키오스크·진동벨을 도입하세요." (좌석 24석 확장 불가·인력 2명·예산 제약 정면 위반)

**[After — 내 카페 파트너]**
- 실행 쿼리:
  ```sql
  SELECT menu_name, CASE WHEN EXTRACT(DOW FROM date) IN (0,6) THEN '주말' ELSE '평일' END daytype, ROUND(AVG(quantity)) avg_qty
  FROM public.cafe_sales WHERE category='디저트' GROUP BY 1,2;
  ```
- 결과: 주말 디저트 **토 55개·일 37개**(평균 46개/일). 메뉴별 주말 일평균: 초코쿠키 25·크로플 14·치즈케이크 8. (my_cafe.md "주말 디저트 매진 잦음" → 판매량은 실수요의 하한)
- 답변(좌석·인력·예산 불변): ① **주말 사전 베이킹(예약 생산)** — 보관 쉬운 초코쿠키·크로플을 금밤~토오전 배치 생산. ② **테이크아웃·예약 분리**로 좌석 회전과 포장 줄을 분리(비용 0). ③ 주말 한정 **세트 1~2종**으로 2인 운영 응대 단순화. 좌석 증설·증원은 제약상 제외.

### Q4. 데이터가 준 가장 중요한 인사이트 1개 + 실행 제안

- 실행 쿼리: `SELECT menu_name, daytype, ROUND(AVG(quantity)) FROM cafe_sales WHERE category='디저트' GROUP BY ...` (평일 5일 vs 주말 2일 묶음, n 충분)
- 결과: **치즈케이크 평일 16개/일 vs 주말 8개/일**(평일 2배), **초코쿠키 주말 25 vs 평일 13**(주말 약 2배).
- **인사이트**: 통념과 반대로 고가 시그니처(치즈케이크 6,500원)는 **평일**에 더 팔리고, 저단가 초코쿠키(3,000원)는 **주말**에 몰린다. 평일=직장인·카공의 단품 고가 수요, 주말=모임의 저가·다개수 수요.
- **실행 제안(제약 준수)**: 평일은 **치즈케이크+커피 객단가 세트**, 주말은 **초코쿠키·크로플 사전 배치 생산**. 한 줄 원칙 = **"평일은 단가, 주말은 물량"** — 같은 디저트 자산을 요일별로 다르게 운용해 좌석·인력 증설 없이 매출을 올린다.

> *전 항목 7일 스냅샷 기반이라 방향성 참고. 시간대·원가 컬럼을 1~2주 더 쌓으면 평일 한산 '시간대'와 메뉴별 마진까지 정밀 타겟 가능.*
