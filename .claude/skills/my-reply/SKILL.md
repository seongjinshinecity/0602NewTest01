# my-reply — shinecity 말투 답장 초안

받은 메시지(메일·슬랙·카톡)에 **shinecity 말투**로 답장 초안을 작성한다.

## 0. 먼저 확인할 것 (없으면 물어보고 진행)

답장은 알맹이가 있어야 한다. 아래가 안 주어졌으면 짧게 되묻는다.

1. **원본 메시지** — 무엇에 대한 답장인지 (붙여넣기 또는 요지)
2. **채널** — 메일 / 슬랙 / 카톡 중 무엇인지 (명시 안 됐으면 원본 형식으로 추정)
3. **받는 사람과의 관계** — 사내 동료 / 상사 / 외부 거래처 / 친한 사이 (격식 수위 결정)
4. **전하려는 핵심** — 수락 / 거절 / 일정조율 / 질문 답변 등

채널·관계가 명백하면 묻지 말고 바로 초안을 쓴다. 핵심 내용이 비면 빈칸 템플릿(`[ ]`)으로 먼저 뽑는다.

## 1. 톤 기준 — my-voice.md를 따른다

`.claude/projects/.../memory/my-voice.md`의 말투 성향을 그대로 가져온다:

- **담백·직설·간결.** 군더더기 서론·잡담·감탄 없음. "무엇을 / 언제 / 어떻게"만.
- **이모지·느낌표 자제**, `ㅋㅋ/ㅎㅎ` 안 씀(채널 예외는 §2).
- **한 메시지 = 한 용건** 원칙. 여러 건이면 항목으로 끊어 적음.
- 표기 선호: `푸쉬`, 영어 명령어/툴명은 원문 그대로(commit/push/npm 등).

### ⚠ 핵심 주의 — 어미는 그대로 쓰지 말 것

my-voice의 어미는 **AI에게 지시할 때의 반말 명령형 `~해줘`**다. 사람에게 보내는 답장에는 그대로 쓰면 무례하다.
→ **성향(간결·직설·담백)만 가져오고, 어미는 받는 사람과의 관계(§3)에 맞춰 조절한다.**

## 2. 채널별 조절 (길이·격식·이모지)

| 채널 | 길이 | 격식 / 어미 | 이모지·부호 | 형식 |
|---|---|---|---|---|
| **메일** | 가장 김. 인사 한 줄 + 본문 + 마무리 | 가장 격식. `~합니다/~드립니다/부탁드립니다` | 없음 | 제목(`Re: …`), 호칭, 서명 포함 |
| **슬랙** | 중간. 인사 생략 가능, 용건 바로 | 가벼운 존댓말 `~할게요/~될까요` 또는 동료면 반존대 | 거의 없음. 필요시 👍/✅ 정도만 | 줄바꿈·불릿 활용, 스레드 의식 |
| **카톡** | 가장 짧음. 한두 문장 | 사이대로. 친하면 반말, 아니면 `~요` | 채널 특성상 1~2개 허용(과하지 않게) | 짧은 메시지 여러 줄 가능 |

원칙: **메일로 갈수록 길고 격식 ↑, 카톡으로 갈수록 짧고 캐주얼 ↑.** 그래도 baseline은 항상 "간결·담백"이다.

## 3. 관계별 어미

- **상사 / 외부 거래처**: 정식 존댓말 (`~하겠습니다`, `~부탁드립니다`, `확인 부탁드립니다`)
- **사내 동료**: 가벼운 존댓말 (`~할게요`, `~될까요`, `좋습니다`) — 과한 격식체 피함
- **친한 사이**: 반말 가능하되 my-voice 그대로의 명령형은 지양, 자연스러운 평어

## 4. 출력 방식

1. **초안 본문**을 채널 형식에 맞춰 바로 제시(메일이면 제목·서명 포함).
2. 채울 값이 비면 `[날짜]`, `[시간]` 같은 `[ ]` 빈칸으로 두고, 무엇을 채워야 하는지 한 줄로 안내.
3. 끝에 **톤 메모** 한 줄: 어떤 격식/길이로 맞췄는지 짧게 설명.
4. 사용자가 채울 값을 주면 완성본으로 다시 정리.

## 5. 피해야 할 것 (Don't)

- ❌ my-voice 반말 명령형(`~해줘`)을 사람 답장에 그대로 쓰기
- ❌ 장황한 서론·과한 공손체("바쁘신 와중에 죄송하지만…" 남발)
- ❌ 이모지·느낌표 남발 (카톡 1~2개 예외 외)
- ❌ 한 답장에 용건 여러 개 뒤섞기 → 항목으로 분리
- ❌ 원본 메시지의 핵심 질문을 빠뜨리고 두루뭉술하게 답하기
